ЭТАП 2 — ЖИВОЙ ПАТРУЛЬ (Кнопка REPORT = Люди)
═══════════════════════════════════════════════════════
Суть: у каждой карточки идеи — кнопка жалобы. После 3 жалоб пост скрывается.

Реализуй:
- SQL-миграция: новая таблица reports:
    id UUID PRIMARY KEY DEFAULT gen_random_uuid()
    idea_id UUID REFERENCES ideas(id)
    reporter_user_id UUID REFERENCES users(id)
    created_at TIMESTAMPTZ DEFAULT now()
    UNIQUE(idea_id, reporter_user_id)  -- один юзер = одна жалоба
- SQL-миграция: добавить поля в таблицу ideas:
    report_count INT DEFAULT 0
    status TEXT DEFAULT 'active'  -- active | hidden | banned | immune
- Supabase Edge Function "submit-report":
    · Проверяет, не жаловался ли этот юзер на этот пост уже
    · Инкрементирует report_count
    · Если report_count >= 3 → ставит status = 'hidden', добавляет в moderation_queue
- Кнопка [ ! REPORT ] на каждой карточке в ленте
- Лента фильтрует: показывать только status IN ('active', 'immune')

ЭТАП 3 — КИБЕР-СУДЬЯ (Gemini 1.5 Flash API = ИИ №2)
═══════════════════════════════════════════════════════
Суть: пост со статусом 'hidden' → умный ИИ выносит вердикт BAN или ALLOW.
Endpoint: Google Gemini 1.5 Flash API
Ключ: берётся из переменной окружения GEMINI_API_KEY

Реализуй:
- SQL-миграция: новые таблицы:
    moderation_queue: id, idea_id, queued_at, processed_at, verdict, ai_reasoning
    banned_posts: id, idea_id, original_text, banned_at, ai_reasoning (архив для апелляций)
- Supabase Edge Function "cyber-judge":
    · Берёт первый необработанный пост из moderation_queue (НЕ параллельно, по одному!)
    · Формирует промпт для Gemini:
      "На этот пост платформы SPARK поступили жалобы от пользователей.
       Текст поста: [ТЕКСТ]
       Внимательно проанализируй содержимое. Это реальный скам, мошенничество или нарушение правил?
       Или это нормальный пост, на который просто пожаловались хейтеры?
       Верни СТРОГО JSON без лишнего текста:
       {\"verdict\": \"BAN\" | \"ALLOW\", \"reason\": \"краткое объяснение на русском\"}"
    · Парсит JSON-ответ от Gemini
    · Если verdict = BAN → status = 'banned', запись в banned_posts
    · Если verdict = ALLOW → status = 'immune', пост возвращается в ленту
    · Записывает результат в moderation_queue (processed_at, verdict, ai_reasoning)
